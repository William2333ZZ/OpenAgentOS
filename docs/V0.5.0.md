## 定位

**0.5.0** 在 0.4.0 网络栈之上接入 **Console `/llm`**，经 model-router 在 Guest 内 **mbedTLS 直连** `https://api.deepseek.com`。**不依赖**宿主机 `deepseek-net-gw.py` 或 `10.0.2.2:8443` bridge。

| 能力 | 说明 |
|------|------|
| `/llm <prompt>` | backend=`deepseek`，经 `router_svc` + `CAP_LLM` |
| DNS | slirp/VPN（198.18.x）→ `net_dns_resolve_slirp`；失败则 Guest DoH |
| TLS | mbedTLS 客户端，`net_https_post_ip` |
| API Key | 构建时烘焙 `generated/deepseek_key.h`（来自 `.env`） |
| 继承 0.4.0 | `check-0.5.0` 仍覆盖 fleet ingest + remote TCP |

---

## 快速开始

```bash
cp .env.example .env        # 必填 DEEPSEEK_API_KEY

python3 tools/fleet-collector.py --host 0.0.0.0 --port 8765
python3 tools/remote-gateway.py --port 5557
# 不要运行 deepseek-net-gw.py

make run-riscv-0.5.0
make check-0.5.0            # 别名 check-llm-console (~75s，含 HTTPS 往返)
```

## 架构（数据路径）

```
Console /llm
    → agent_svc_llm(..., "deepseek")
    → router_svc (CAP_LLM)
    → llm_deepseek_query()
         → net_dns_resolve_slirp / net_dns_resolve (DoH)
         → net_https_post_ip(api.deepseek.com)
         → JSON extract content
```

关键源码：`user/console_svc.c`、`user/router_svc.o`、`kernel/llm_deepseek.c`、`kernel/tls_client.c`。

---

## 构建说明

- `kernel-console-v050.elf` 仅依赖 `generated/deepseek_key.h`，**不再**需要 `mk-deepseek-host.sh`（0.5.0 运行时 DNS，不烘焙 CloudFront IP）。
- `scripts/mk-deepseek-host.sh` 保留给旧版 `kernel-llm-net.elf` / `check-llm-net`，含 `dig`/`host`/DoH 多路回退。
